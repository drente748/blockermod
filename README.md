# BlockerMod

تطبيق أندرويد لحجب المحتوى المدمّر (الإباحية والإعلانات) ومنع التشتت، يعمل كتطبيق مستقل بلا
خادم ولا حساب.

> الحالة الحالية: **الهيكل الأساسي فقط**. المحرك لم يُكتب بعد، ولا توجد واجهة مستخدم.
> المرجع الكامل للحالة في `PROGRESS.md`.

## فلسفة المشروع

المنتج يعالج مشكلة واحدة بدقّة: **أن يجد المستخدم نافذةً لا يستطيع لنفسه إغلاقها**.

- الحجب **محلي بالكامل**: القواعد على الجهاز، والمطابقة على الجهاز، ولا تغادر أي بيانات النطاق.
- الحجب **فوري**: لا تحميل قوائم من الخادم، ولا انتظار مزامنة، ولا "آخر تحديث".
- الحجب **شامل**: يعمل على مستوى النظام لا على مستوى متصفّح واحد، فلا يُلتفّ عليه بتطبيق آخر.
- غياب **الشاشات الزائدة**: التطبيق أداة لا لوحة تحكم؛ كل شاشة يجب أن تخدم قراراً واحداً واضحاً.

## نموذج التوزيع

| البند | القرار |
|---|---|
| شكل التسليم | ملف APK مستقل يُثبَّت مباشرة على الجهاز |
| التحديثات | لا نظام تحديث تلقائي ولا خادم إصدارات |
| التوقيع | مفتاح توقيع واحد يُدار داخلياً، بلا مفاتيح مشتركة مع أي طرف |
| متجر التطبيقات | غير مطلوب؛ التطبيق لا يعتمد على أي خدمة من المتاجر |
| الاتصال الخدمي | **غير محسومة** — تُترك مفتوحة للقرار لاحقًا؛ لا يوجد أي اتصال حاليًا |
| بيانات المستخدم | تُقرَّر لاحقًا حسب رغبتك |
| النسخ الاحتياطي | **معطّل بالكامل**: لا نسخة سحابية ولا نقل بيانات بين الأجهزة |
| الترخيص | Apache-2.0 (انظر `LICENSE`) |

**عندما يُبنى المحرك:** سيستخدم الجهاز شبكة الاتصال لتمرير استعلامات DNS عبر النفق (متطلَّب تقني)؛
أي اتصال خارج هذا الخيار ومتروك لقرار لاحق.

### لماذا لا تحديثات؟

لأن التحديث الآلي يفرض بالضرورة جهة اتصال (خادم إصدارات) ومعرّف تثبيت وسجلّ تحديثات. هذه التكلفة
تتناقض مع مبدأ "الأداة التي تحمي التركيز لا تفتح باباً خلفياً على بيانات المستخدم". التحديث يتم
بتثبيت APK جديد يدوياً.

## المبادئ التصميمية

1. **المحرك قبل الواجهة**: لا شاشة قبل أن يعمل محرك الحجب.
2. **سياسة الاتصال مفتوحة**: لا قرار مسبقًا بشأن الاتصال بالإنترنت؛ تُقرَّر لاحقًا.
3. **بلا إطار DI**: بناء يدوي وصريح، بلا انعكاس.
4. **وحدتان باتجاه واحد**: `:app → :core`، ولا رجوع.
5. **وضع تشغيل واحد**: انظر `ARCHITECTURE.md`.
6. **قابل للاختبار**: منطق الحظر في `:core` Kotlin/JVM خالص، فيُختبر على الجهاز الحقيقي للمطور
   (JVM) بلا محاكي.
7. **بلا انعكاس على داخليات النظام**: لا تعديل لحقول `static final` ولا وصول لحقول خاصة.

```
blockermod/
├── settings.gradle.kts           # الوحدات: app وcore
├── build.gradle.kts              # إضافة التطبيق (نسخة واحدة من كتالوج الإصدارات)
├── gradle/
│   ├── libs.versions.toml        # كتالوج الإصدارات (إضافة + مكتبات)
│   └── wrapper/                  # مُشغّل Gradle المُثبَّت
├── gradle.properties
├── gradlew / gradlew.bat
├── LICENSE                       # Apache-2.0
├── core/                         # Kotlin/JVM خالص — بلا Android
│   ├── build.gradle.kts
│   └── src/
│       ├── main/kotlin/com/blockermod/core/   # BlockingEngine, BlockingResult, BlockReason, BlockingState, DomainMatcher
│       └── test/kotlin/com/blockermod/core/   # اختبارات JVM للمطابقة والقرار
└── app/
    ├── build.gradle.kts          # إعدادات الوحدة: SDK، الإصدارات، الاعتماديات
    └── src/main/
        ├── AndroidManifest.xml   # الأذونات + نقطة دخول المحرك (VpnService)
        ├── res/values/strings.xml
        ├── res/xml/              # استثناء كامل من النسخ الاحتياطي ونقل البيانات
        └── java/com/blockermod/
            ├── BlockermodApp.kt        # Application
            └── platform/
                ├── vpn/BlockerVpnService.kt       # مضيف المحرك (بلا منطق بعد)
                ├── deviceowner/DeviceOwnerManager.kt  # عقد الوضع المستقبلي
                └── applock/AppLockManager.kt          # عقد مستقبلي
```

لغة التطبيق (الشيفرة والموارد والتسميات) إنجليزية. وثائق المشروع عربية.

## قضايا تشغيلية

القضايا التي ستحدّد نجاح المحرك (موقف تشفير DNS، حماية المقابس، مسار الإقلاع دائم الاتصال، وتجريد
مُطابِق النطاقات) موضّحة وحاسمة في `ARCHITECTURE.md` ضمن أقسام "DNS Encryption Policy"،
"Socket Protection"، "Always-On Startup Path" و"Domain Matcher Abstraction". تُحال عليها ولا
تُكرَّر هنا.

## البناء والتحقق

```bash
./gradlew :core:build :core:test   # منطق الحظر: ترجمة واختبارات JVM
./gradlew :app:assembleDebug       # التطبيق: حزمة تحقق
./gradlew :app:lintDebug           # فحص الأخطاء
```

> لا تُنتَج نسخة نهائية للتوزيع في هذه المرحلة: لا يوجد محرك ولا واجهة بعد.
> `assembleRelease` تُستخدم للتحقق فقط وليست خطوة إطلاق.

## سياسة الاتصال بالإنترنت

سياسة الاتصال بالإنترنت **مفتوحة للقرار اللاحق** — لا تُقرَّر في هذا البناء:

- لا يوجد أي اتصال بأي خادم في الكود الحالي ولا في الاعتمادات، ولا أي مكوّن يقيس استخدامك.
- هذا البناء لا يفرض أي قيد ولا يحجز أي قرار مستقبلي (لا تمنع منه ولا تلزم به شيئًا: تحديثًا، قياسًا،
  إحصاءً، أو ما شابه) — القرار النهائي لك لاحقًا حسب رغبتك.
- عند بناء المحرك، سيستخدم الجهاز شبكة الاتصال لتمرير استعلامات DNS عبر النفق — وهذا متطلَّب تقني
  لعمل المحرك نفسه، وليس قيدًا على باقي القرارات.

## الخصوصية

- لا يوجد أي قياس أو تتبع في الكود الحالي، وقرار إعادة الفتح لاحقًا بيدك.
- لا تخزين سحابي لقوائم الحظر: القواعد مضمّنة في التطبيق وتُحدَّث مع الإصدار (بتثبيت APK يدوي فقط).
- النسخ الاحتياطي السحابي ونقل البيانات بين الأجهزة معطّلان على كل الإصدارات.
